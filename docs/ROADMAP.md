# ROADMAP — БаЛаЛайка

Статус проекта: планирование
Дата: 2026-11-06

План рассчитан на 7 дней разработки + 3 дня буфера. Внешний срок по ТЗ — 10 дней.

## Правила ведения

- Статусы этапа: пусто → `в работе` → `готово`.
- Этап считается готовым только после прохождения его DoD и smoke-сценария.
- Следующий этап не начинается, пока предыдущий не закрыт; внутри этапа задачи можно вести параллельно.
- Каждый этап заканчивается обновлением этого файла и, при необходимости, ADR.
- Код без миграции, тестов и документации не считается готовым.
- P2-функции не блокируют сдачу MVP.

## Этап 0. Foundation

**Статус:** готово

**Цель:** получить запускаемый каркас и зафиксировать контракты.

**Задачи:**

- Каталоги `backend/`, `frontend/`, `deploy/`, `docs/` по `architecture.md`.
- `backend/pyproject.toml`, зависимости, Ruff, mypy, pytest, `make check`.
- Перенос `pyproject.toml`, `poetry.lock` (и `poetry.toml`, если нужен) из корня в `backend/` — отдельная задача.
- Конфиг через env, `.env.example`, запрет секретов в git.
- Async SQLAlchemy, Alembic, первая миграция.
- `deploy/docker-compose.yml`: nginx, backend, postgres, redis, minio, minio-init.
- Health endpoints `/healthz`, `/readyz`.
- Базовый шаблон Jinja и статика в `frontend/`; `frontend/package.json` для dev-сборки CSS.
- `.gitattributes` с LF для `*.sh`.
- README-каркас с быстрым стартом.

MinIO-клиент в приложении, worker, ARQ и upload в этап 0 не входят и остаются на этапе 2.

**DoD:**

- `cd deploy && docker compose up` поднимает пустое приложение.
- `alembic upgrade head` проходит на чистой БД.
- `/healthz` отвечает 200.
- `make check` зелёный.
- Нет `TODO` и заглушек в `develop`.

**Smoke:** поднять compose, открыть `/`, `/docs`, `/healthz`.

## Этап 1. Auth, users, channels

**Цель:** рабочий вход и базовые сущности пользователя.

**Задачи:**

- Argon2id, регистрация, вход, logout, logout-all.

**DoD:**

- Вход/выход работают через cookie.
- CSRF-запрос без токена отклоняется.
- Роль нельзя повысить через API.
- Тесты auth зелёные.

**Smoke:** зарегистрироваться, выйти, войти, открыть профиль.

## Этап 2. Upload & processing

**Статус:**

**Цель:** загрузка файла, обработка и статусы.

**Задачи:**

- MinIO-клиент, бакеты `incoming-videos`, `media`, `raw-videos`.
- `minio-init`: бакеты, lifecycle, scoped-пользователь.
- `POST /videos`, `POST /videos/{id}/upload-url`, `POST /videos/{id}/complete`.
- Presigned POST: 500 МБ, `video/*`, expiry 15 минут.
- Nginx-прокси `/incoming-videos/` с сохранением Host.
- Проверка `HEAD` после загрузки; идемпотентный complete.
- ARQ + Redis, job `video:{id}:process`.
- Worker: ffprobe, 30 минут, ffmpeg 720p faststart, thumbnail.
- Статусы `draft/uploaded/processing/ready/rejected`.
- Reconciler для `uploaded` и зависших `processing`.
- Cleanup `incoming-videos` через lifecycle.
- Страница загрузки с drag-and-drop и прогрессом.
- Тесты: лимит, неверный тип, чужой video_id, повторный complete, ffprobe.

**DoD:**

- Маленький MP4 загружается, обрабатывается и получает `ready`.
- Файл >500 МБ отклоняется MinIO.
- Без `complete` видео не становится доступным.
- Чужой пользователь не может завершить загрузку.
- Ошибка ffmpeg даёт `rejected`, исходник сохранён.
- Smoke на чистой VM с IP.

**Smoke:** загрузить клип, дождаться `ready`, проверить объект в `media`.

## Этап 3. Watch, feed, search

**Статус:**

**Цель:** основной сценарий просмотра и обнаружения.

**Задачи:**

- Главная лента: `ready`, `visible`, `public`, сортировка по `published_at`.
- Watch-страница: плеер, заголовок, канал, описание, счётчики; блок комментариев подключается на этапе 4.
- `GET /media/videos/{id}` с Range 206/416.
- `GET /media/thumbnails/{id}`.
- Канал: вкладки «Видео» и «Плейлисты»; кнопка подписки появляется на этапе 4.
- Поиск по названию и каналу, `pg_trgm`, keyset-пагинация.
- Метаданные: длительность, разрешение, дата, просмотры.
- Тесты: Range, 404 для draft, фильтры ленты и поиска.

**DoD:**

- Публичное видео играет с перемоткой.
- Draft/rejected не видны в ленте и поиске.
- Поиск находит по части названия.
- Пагинация не дублирует записи.

**Smoke:** найти видео, открыть, перемотать, вернуться в ленту.

## Этап 4. Engagement

**Статус:**

**Цель:** социальные действия и метрики.

**Задачи:**

- Лайки: unique `(user_id, video_id)`, идемпотентность, счётчик.
- Комментарии: создание, удаление автором, счётчик, сортировка.
- Подписки: unique `(subscriber_id, channel_id)`, кнопка на канале.
- Плейлисты: создание, добавление/удаление видео, порядок.
- Просмотры: `views_count`, инкремент при watch.
- Лента подписок — P2, если успеваем.
- Тесты: повторный лайк, чужая подписка, счётчики, права на удаление комментария.

**DoD:**

- Лайк и комментарий работают из UI и API.
- Повторный лайк не создаёт дубль.
- Подписка отображается на канале.
- Плейлист сохраняет порядок.
- Счётчики согласованы с действиями.

**Smoke:** лайк, комментарий, подписка, плейлист.

## Этап 5. Privacy & ACL

**Статус:**

**Цель:** private/unlisted и управление доступом.

**Задачи:**

- `visibility` для видео; `unlisted` исключён из лент/поиска/канала.
- `video_acl`; выдача и отзыв доступа по handle.
- UI настроек приватности для владельца.
- Приватные плейлисты; фильтрация элементов.
- Проверка `can_view` на всех поверхностях: feed, search, channel, playlist, watch, thumbnail, stream, API.
- 404 для чужих.
- Тесты IDOR на каждую поверхность.

**DoD:**

- Private-видео не видно никому, кроме owner и ACL.
- Unlisted доступно по ссылке, но не в списках.
- Отзыв доступа сразу даёт 404.
- Приватный плейлист не раскрывает состав.
- Security-тесты зелёные.

**Smoke:** private → чужой 404 → выдать доступ → 200 → отозвать → 404.

## Этап 6. Moderation & admin

**Статус:**

**Цель:** жалобы, скрытие и аудит.

**Задачи:**

- `reports` по видео: причина, комментарий, статус.
- Очередь модератора, просмотр жалобы.
- Hide/restore видео; `moderation_status`.
- Проверка, что hidden недоступен публике, но виден owner/moderator.
- `audit_log` для действий модератора и ролей.
- Админ: список пользователей, смена роли, запрет self-escalation.
- Rate limit жалоб.
- Тесты ролей, hide/restore, аудита, доступа к private по жалобе.

**DoD:**

- Пользователь создаёт жалобу.
- Модератор скрывает видео; публика получает 404.
- Restore возвращает видео.
- Действие есть в аудите.
- Пользователь не может получить moderator/admin.

**Smoke:** жалоба → hide → 404 → restore → 200.

## Риски и ранние проверки

| Риск | Когда проверяем | Действие |
|---|---|---|
| SigV4 presigned POST через nginx | Этап 2, первый день | Smoke на чистой VM; при провале — backend-mediated upload |
| ffmpeg на малой VM | Этап 2 | Короткие клипы, 720p, timeout, один worker |
| HTTP + Secure cookie | Этап 1 | `SESSION_COOKIE_SECURE=false`, проверить login |
| MinIO/Postgres startup order | Этап 0 | Healthchecks и `depends_on: service_healthy` |
| Потеря ARQ job | Этап 2 | Reconciler и идемпотентный job id |
| Утечка private через списки | Этап 5 | Тесты на все read-поверхности |
| Долгий UI-полиш | Этап 7 | Сначала функциональность, потом скриншоты |

## Definition of Done проекта

- Сценарий «регистрация → загрузка → просмотр → лайк → комментарий» работает на чистой VM.
- Каналы, поиск, плейлисты, подписки, приватность и модерация доступны.
- `/docs` работает.
- Seed наполняет демо-данными.
- Тесты и линтеры зелёные.
- README и docs актуальны.
- Секретов в репозитории нет.
- Git-история осмысленная: ветки по задачам, Conventional Commits.
