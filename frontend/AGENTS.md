# AGENTS.md — frontend

## 1. Область

Каталог `frontend/` содержит Jinja2-шаблоны, статику и dev-сборку CSS. Правила действуют для `frontend/templates/` и `frontend/static/`.

- Стек: Jinja2 SSR + precompiled Tailwind CSS + vanilla ES-модули.
- Node используется только для dev-сборки CSS и не нужен в runtime.
- Backend и деплой живут в `backend/` и `deploy/`; не добавляй их детали сюда.
- UI-решения — ADR-004 и ADR-011. Источник истины по решениям — `docs/decisions.md`.

## 2. Структура

```text
frontend/
├── templates/
│   ├── base.html          # каркас: topbar, sidebar, flash, подключение CSS/JS
│   ├── partials/          # topbar, sidebar, video-card, pagination, flash
│   ├── macros/            # переиспользуемые Jinja-макросы
│   ├── pages/             # home, watch, channel, search, upload, auth, moderation
│   └── errors/            # 404, 403, 500
├── static/
│   ├── css/               # собранный Tailwind, коммитится
│   ├── js/                # ES-модули по страницам и общие утилиты
│   └── img/               # логотип, иконки, плейсхолдеры
└── package.json           # только dev-сборка Tailwind
```

- Один экран — один шаблон в `pages/`; общие блоки выносятся в `partials/` или `macros/`.
- Имена файлов и CSS-классов — английские; текст интерфейса — русский.
- Статические файлы подключаются через `url_for('static', ...)`, без абсолютных путей.

## 3. Jinja2

- Автоэкранирование включено; `|safe` допускается только для доверенного HTML и с обоснованием.
- Все ссылки и формы строятся через `url_for`, а не руками.
- Базовый шаблон — `base.html`; страницы используют `{% extends %}` и блоки.
- Повторяющиеся элементы — макросы или `include`, без копирования разметки.
- В шаблоне нет бизнес-логики, SQL, проверок ролей и вычисления прав. Шаблон отображает подготовленный контекст.
- Условный показ кнопок — только UX; защита выполняется на backend.
- Формы содержат CSRF-токен; JSON-запросы берут его из `<meta name="csrf-token">`.
- Ошибки и пустые состояния показываются по-русски и не раскрывают внутренние детали.

## 4. JavaScript

- Только vanilla ES-модули; без React/Vue/jQuery и без SPA-роутинга.
- Один модуль на страницу или виджет; общие функции — в `static/js/lib/`.
- Динамика через `fetch` к JSON API; базовая форма должна работать без JS, где это возможно.
- Прогрессивное улучшение: сначала рабочая форма/ссылка, затем улучшение поведением.
- Никаких inline `<script>`, `onclick` и `javascript:`-ссылок.
- Состояние загрузки, ошибки и повтор действия обрабатываются явно; `console.error` не остаётся в готовом коде.
- Не логируй токены, пароли, CSRF и персональные данные.
- Внешние CDN и сторонние скрипты запрещены: CSP должна оставаться строгой.

## 5. CSS и Tailwind

- Tailwind собирается заранее в `static/css/`; собранный файл коммитится.
- Node-сборка: `npm ci`, `npm run build:css`; во время разработки — `npm run watch:css`.
- Tailwind CDN и runtime-компиляция запрещены.
- Классы — утилитарные Tailwind; сложные повторяемые паттерны — через `@layer components`, а не копипаст.
- Inline-стили и `<style>` в шаблонах запрещены, кроме CSS-переменных темы.
- Не удаляй классы, которые используются в шаблонах; проверяй сборку после правок.
- Светлая тема по умолчанию; тёмная — P2 и не блокирует MVP.

## 6. UI-чеклист YouTube

Каждый экран сверяется с оригиналом по расположению и составу элементов:

- **Topbar:** логотип, центральный поиск, кнопка загрузки, аватар/вход.
- **Sidebar:** главная, подписки, плейлисты, история/мои видео; активный пункт выделен.
- **Grid:** карточки с превью 16:9, длительностью, названием, каналом, просмотрами и датой.
- **Watch:** плеер, заголовок, канал и подписка, лайк, описание, комментарии; рекомендации не обязательны.
- **Channel:** баннер, аватар, название, подписчики, вкладки «Видео» и «Плейлисты», кнопка подписки.
- **Search:** строка запроса, количество результатов, список карточек, пустое состояние.
- **Upload:** drag-and-drop, выбранный файл, прогресс, метаданные, видимость, статус обработки.
- **Moderation:** очередь жалоб, причина, видео, действия hide/restore, понятные статусы.

- Сохраняй привычные пропорции, отступы и иерархию; не изобретай новый визуальный язык.
- Все 7 экранов из ТЗ должны быть доступны из навигации или прямым URL.

## 7. Доступность и CSP

- Semantic HTML: `header`, `nav`, `main`, `section`, `button`, `label`.
- У полей есть `label`; у изображений — осмысленный `alt`; у кнопок — доступное имя.
- Фокус видим, порядок табуляции логичен, интерфейс управляется с клавиатуры.
- Контраст текста и элементов соответствует WCAG AA.
- Не полагайся только на цвет для статусов и ошибок.
- CSP: без inline-скриптов, inline-стилей и внешних источников; всё подключается файлами.
- Видео и изображения имеют `width`/`height` или соотношение сторон, чтобы не прыгал layout.

## 8. Скриншот-ревью

Перед сдачей экрана проверь:

- ширины 1280 px и 768 px; нет горизонтального скролла и наложений;
- topbar и sidebar не перекрывают контент, сетка не ломается;
- пустые состояния, длинные названия и ошибки выглядят корректно;
- в консоли браузера нет ошибок и предупреждений CSP;
- все ссылки и формы ведут на существующие маршруты.

Скриншоты прикладываются к ревью задачи; расхождения с чеклистом фиксируются до коммита.

## 9. Команды

```bash
cd frontend
npm ci
npm run build:css
npm run watch:css
```

- `npm run build:css` обязателен перед коммитом, если менялись шаблоны или стили.
- `node_modules/` не коммитится; собранный CSS коммитится.

## 10. Готовность frontend-изменения

- Экран открывается на 1280 и 768 без ошибок в консоли.
- Разметка использует `url_for`, автоэкранирование и общий каркас.
- Нет inline-стилей, inline-обработчиков и внешних CDN.
- UI на русском, идентификаторы на английском.
- Собранный CSS актуален, шаблоны не содержат мёртвых ссылок.
